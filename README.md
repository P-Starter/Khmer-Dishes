# 🍳 Khmer Dishes — Cambodian Recipe Catalog

An open, **bilingual** (English + ខ្មែរ) structured catalog of **1,060+ Cambodian
(Khmer) dishes** — each with a trilingual name (Khmer / romanized / English),
structured ingredients, and step-by-step *how-to-cook* instructions — plus a
lightweight, searchable webview that runs anywhere as a static site.

> **Live site:** https://p-starter.github.io/Khmer-Dishes/

The goal is to grow into the most complete, machine-readable reference of Khmer
home cooking — and to recommend a **daily Khmer dish** to anyone learning to cook it.

---

## ✨ Features

- **1,060 dishes** across 14 categories (stir-fry, soup, curry, grilled, fried, braised, steamed, salad, noodles, rice, dip, dessert, drink, snack).
- **Trilingual names** — Khmer script · romanization · English.
- **Bilingual content** (EN + ខ្មែរ) — Khmer translations of descriptions, cooking steps + chef's tips, ingredient items and notes, equipment, and section titles. Native readers can follow the recipe end-to-end in Khmer.
- **Real cooking steps** — grouped ingredients + numbered instructions with chef's tips.
- **Searchable webview** — typo-tolerant fuzzy search, filters (category / protein / diet / spice), a deterministic **dish of the day**, and a **full-screen recipe dialog** on big screens (sticky ingredients sidebar + roomy method area).
- **Open data** — slim catalog index + per-dish JSON files, all validated by a published [JSON Schema](#-data--schema). Lazy-loaded so the page stays fast as the catalog grows.
- **Zero backend** — pure static files; deploys free on GitHub Pages.

## 🚀 Quick start

**Just want to use it?** Open the live site:
👉 **https://p-starter.github.io/Khmer-Dishes/**

**Want to run it locally?** The page lazy-loads from `build/`, so it needs to be
**served** — opening `index.html` directly via `file://` will fail with
*"Failed to fetch"* (browsers block local file fetches by design).

```bash
# from inside the project folder
python -m http.server 8000
# then open http://localhost:8000  (not the file path)
```

**Re-build from sources** (only when you edit a YAML or extend the generator):

```bash
python generate_khmer_menu.py   # regenerate combinatorial YAMLs (optional)
python build_catalog.py         # merge dishes/* into build/
```

`build/` is committed so GitHub Pages serves the latest build without any CI step.

## 📦 Repository structure

| Path | Purpose |
|------|---------|
| `index.html` | Self-contained webview. Lazy-loads `build/index.json` on boot and `build/dishes/<slug>.json` per recipe. |
| `dishes/manual/<slug>.yaml` | **Hand-authored dishes — the source of truth.** Edit these, or add new ones, to contribute. |
| `dishes/generated/<slug>.yaml` | Combinatorial dishes (cooking method × style × protein) written by `generate_khmer_menu.py`. Regeneratable, safe to wipe. |
| `build/index.json` | Slim catalog (~600 KB) the page boots from. |
| `build/dishes/<slug>.json` | Per-dish detail, fetched when a recipe is opened (~3–6 KB each). |
| `build/khmer_menu.json` | Bulk dataset (`{ meta, recipes[] }`) for downstream consumers. |
| `khmer_menu.schema.json` | JSON Schema (draft-07) — the data contract. |
| `build_catalog.py` | Build script — merges `dishes/manual/` + `dishes/generated/` into `build/`. |
| `generate_khmer_menu.py` | Generator for combinatorial dishes (extend the style/protein lists here). |
| `fetch_images.py` | Optional: fetch one stock photo per dish from Pexels / Unsplash, gated for Khmer-relevance. |
| `images/dishes/<slug>.jpg` | Per-dish photos. Missing photos render as the placeholder. |
| `credits.html` | Auto-generated photo credits (regenerated by `fetch_images.py`). |
| `.nojekyll` | Marker so GitHub Pages serves the static assets as-is. |

## 🧾 Data & schema

Every dish is validated against [`khmer_menu.schema.json`](./khmer_menu.schema.json).
You can consume the catalog three ways:

- **Bulk dataset** — [`build/khmer_menu.json`](./build/khmer_menu.json) (`{ meta, recipes[] }`, all dishes).
- **Slim index** — [`build/index.json`](./build/index.json) (~620 KB, drives the webview's grid + search).
- **Per-dish JSON** — `build/dishes/<slug>.json` (~3–6 KB each, fetched on demand).

The bulk file looks like:

```jsonc
{
  "meta": {
    "schemaVersion": "1.0",
    "cuisine": "Khmer",
    "count": 1060,
    "categories": ["stir-fry", "soup", "curry", "..."],
    "language": { "primary": "en", "names": ["km", "romanized", "en"] }
  },
  "recipes": [ /* … */ ]
}
```

### Recipe object

```jsonc
{
  "id": "khm-0001",                       // stable unique id
  "slug": "fish-amok",                    // URL-safe slug
  "name": { "km": "អាម៉ុកត្រី", "romanized": "Amok Trey", "en": "Fish Amok" },
  "category": "curry",
  "subcategory": "amok",
  "cuisine": "Khmer",
  "description":   "Cambodia's national dish — a silky steamed coconut fish curry…",
  "descriptionKm": "ម្ហូបជាតិកម្ពុជា — ការីត្រីចំហុយក្នុងស្លឹកចេក…",  // bilingual
  "image": "images/dishes/fish-amok.jpg", // per-dish; falls back to placeholder
  "imageFamily": "fish-amok",             // grouping metadata (kept for contributor handoff)
  "tags": ["signature", "fish", "steamed", "coconut"],
  "dietary": ["pescatarian", "gluten-free"],
  "spiceLevel": 1,                        // 0–5
  "difficulty": "medium",                 // easy | medium | hard
  "servings": 4,
  "time": { "prepMinutes": 40, "cookMinutes": 25, "totalMinutes": 65 },
  "kroeung": ["lemongrass", "galangal", "turmeric", "…"],   // the Khmer flavour base
  "equipment":   ["steamer", "banana leaf cups", "mortar and pestle"],
  "equipmentKm": ["ឆ្នាំងចំហុយ", "ពែងស្លឹកចេក", "អង្គ្រែ"], // parallel array
  "ingredients": [
    {
      "group": "main",
      "item":    "snakehead fish fillet",  "itemKm":  "សាច់ត្រី",
      "quantity": 500, "unit": "g",
      "notes":   "sliced",                 "notesKm": "ហាន់"
    }
  ],
  "instructions": [
    {
      "step": 1,
      "text":   "Pound the kroeung to a smooth paste.",
      "textKm": "បុកគ្រឿងលឿងឱ្យល្អិតៗ។",
      "tip":    "Smoothness is everything in amok.",
      "tipKm":  "ភាពល្អិតគឺជាគន្លឹះនៃអាម៉ុក។"
    }
  ]
}
```

### Field reference

| Field | Type | Notes |
|-------|------|-------|
| `id` | string | `khm-NNNN`, unique & stable. |
| `slug` | string | URL-safe, unique. |
| `name` | object | `{ km, romanized, en }` — `en` required. |
| `category` / `subcategory` | string | Menu category + Khmer technique family (`cha`, `samlor`, `amok`, `kho`, …). |
| `description` / `descriptionKm` | string | English + optional Khmer paragraph. |
| `image` / `imageFamily` | string | Per-dish photo path + grouping metadata. Missing photos render the placeholder. |
| `tags` / `dietary` | string[] | `dietary` ∈ `vegetarian, vegan, pescatarian, gluten-free, dairy-free, halal`. |
| `spiceLevel` | int 0–5 | 0 = none, 5 = very hot. |
| `difficulty` | enum | `easy` \| `medium` \| `hard`. |
| `servings` | int | — |
| `time` | object | `prepMinutes`, `cookMinutes`, `totalMinutes`. |
| `kroeung` | string[] | Aromatic paste components. |
| `equipment` / `equipmentKm` | string[] | Tools + optional parallel Khmer array (same length). |
| `ingredients[]` | object[] | `{ group, item, itemKm?, quantity?, unit?, notes?, notesKm? }`. |
| `instructions[]` | object[] | `{ step, text, textKm?, tip?, tipKm? }`. |

### Bilingual coverage today

| Field | EN | ខ្មែរ |
|---|---|---|
| Trilingual names (`name.km` / `romanized` / `en`) | 100% | 100% |
| Recipe description | 100% | **100%** |
| Cooking step text | 100% | ~47% (the common cross-recipe phrases) |
| Iconic dishes (description + every step + every tip) | 5 / 5 | **5 / 5** |
| Ingredient item names | 100% | **~99%** |
| Ingredient prep/notes | 100% | ~87% |

Coverage was authored by hand for the high-leverage items; remaining gaps live
in style-specific sentences and uncommon ingredients, and are great

## 🔁 How the catalog is built

The catalog has **two sources** that combine into one deployable site:

1. **`dishes/manual/*.yaml`** — hand-authored dishes. Iconic signature dishes,
   regional specialties, festival recipes, and any contribution. This is the
   source of truth; edit these directly.
2. **`dishes/generated/*.yaml`** — combinatorial dishes emitted by
   `generate_khmer_menu.py` (every cooking method × style × protein). Safe to
   wipe and regenerate.

The build script merges both, validates against the schema, and emits a slim
index plus per-dish detail files into `build/`:

```bash
python generate_khmer_menu.py   # rewrite dishes/generated/ (only if extending the generator)
python build_catalog.py         # merge dishes/* -> build/index.json + build/dishes/*.json + build/khmer_menu.json
```

`build/` is committed so GitHub Pages serves it with zero CI. The page loads
`build/index.json` (~600 KB) once for the grid + search, then `fetch()`es each
`build/dishes/<slug>.json` (~3–6 KB) only when a user opens that recipe.

When a slug exists in both `dishes/manual/` and `dishes/generated/`, **manual
wins** — that's the contributor-override mechanism for improving a generated dish.

## 🖼️ Dish images (optional)

Each dish gets **its own image slot** at `images/dishes/<slug>.jpg`, fetched one
at a time so protein variants aren't forced to share a misleading photo. A photo
is only kept if its alt-text or page URL contains a clearly Cambodian/Khmer term
(`cambodian`, `khmer`, `amok`, `lok lak`, `kuy teav`, `prahok`, `samlor`,
`kreung`, …). Otherwise the dish keeps the emoji placeholder — **better an honest
placeholder than a wrong photo**.

```bash
# free API key: https://www.pexels.com/api/  or  https://unsplash.com/developers
python fetch_images.py --dry-run                              # preview per-dish queries
python fetch_images.py --source pexels --key YOUR_KEY --limit 10   # test a few
python fetch_images.py --source pexels --key YOUR_KEY              # full run (resumable)
```

Images land in `images/dishes/`, with attribution written to
`images/dishes/attribution.json` and `credits.html`. Curated queries for iconic
dishes live in `QUERY_OVERRIDES` at the top of `fetch_images.py`; the
Khmer-relevance gate is `KHMER_TERMS` in the same file. Both are easy to extend.

## 🤝 Contributing — submit more dishes

**We want this catalog to grow well beyond 1,000 dishes** — toward thousands of
regional, family, festival, and modern Khmer recipes. Two contribution paths:

### 1. Add or improve one dish — write a YAML

The easy path. Drop a single file into `dishes/manual/` and open a PR. No Python,
no generator. Start from any existing manual file as a template:

```yaml
# dishes/manual/my-grandmothers-amok.yaml
id: khm-XXXX            # ask a maintainer / leave blank, build_catalog will assign
slug: my-grandmothers-amok
name:
  km: អាម៉ុករបស់លោកយាយ
  romanized: Amok Robos Lok Yeay
  en: My Grandmother's Amok
category: curry
subcategory: amok
description:   "A regional variant from Battambang, finished with toasted peanuts…"
descriptionKm: "ការីអាម៉ុកពីបាត់ដំបង — បញ្ចប់ដោយសណ្ដែកដីលីង…"
tags: [regional, battambang, fish, signature]
ingredients:
  - { group: main, item: "snakehead fillet", itemKm: "សាច់ត្រី", quantity: 500, unit: g }
  - …
instructions:
  - step: 1
    text:   "Make the kroeung…"
    textKm: "បុកគ្រឿង…"
```

Then run:

```bash
python build_catalog.py   # validates your YAML, rebuilds the site
```

If your slug matches an existing combinatorial dish in `dishes/generated/`,
**your manual version wins** — that's how you improve a generated dish.

### 2. Add a whole *family* of variations — extend the generator

If your contribution is a new cooking technique or aromatic style that should
fan out across many proteins (e.g., a new `CHA_STYLES` entry, or a new vegetable
for `VEG_PAIRS`), extend `generate_khmer_menu.py`:

```bash
python generate_khmer_menu.py   # writes the new YAMLs into dishes/generated/
python build_catalog.py         # merge into build/
```

**Checklist for a good submission**

- [ ] Trilingual name (Khmer script + romanization + English).
- [ ] Correct `category` and a sensible `subcategory`/technique.
- [ ] Authentic `kroeung` / aromatics where relevant.
- [ ] Real, ordered `instructions` a home cook can follow.
- [ ] `ingredients` with quantities and helpful `notes`.
- [ ] `dietary`, `spiceLevel`, and `difficulty` set honestly.
- [ ] Data still validates against the schema.
- [ ] Khmer translations (`descriptionKm`, step `textKm`/`tipKm`, ingredient `itemKm`/`notesKm`) are appreciated but **not required** — if you only contribute English we can fill the Khmer side via the central lookups.

**Extending the Khmer translation layer.** In `generate_khmer_menu.py`, the
finalize section holds the centralized Khmer tables — `KM_DESC_BY_FAMILY`,
`KM_INGREDIENT`, `KM_NOTES`, `KM_EQUIPMENT`, and the regex `PHRASE_RULES`.
Adding a single entry to any of these can cover dozens of recipes at once;
this is one of the most useful contributions.

Open a Pull Request with a short note on the dish and its region/source. 🇰🇭

## 🌐 Deploy (GitHub Pages)

1. **Settings → Pages → Build and deployment → Source:** *Deploy from a branch*.
2. **Branch:** `main` · **Folder:** `/ (root)` → **Save**.
3. The repo must be **public** for free Pages (private needs GitHub Pro).
4. Pages auto-rebuilds on every push to `main`. A `.nojekyll` file ships the assets as-is, and `build/` is committed so deploys need zero CI.
5. To refresh the deployed site after editing dishes, run `python build_catalog.py`, commit `build/`, push.
